# 커리큘럼

BlockOps는 3학년 2학기 DevOps 스터디 워크북(1~7차시와 Prometheus 정리)을 기반으로 단원을 구성합니다. 단원별 매핑, 노드 카탈로그, 시뮬레이션 규칙 후보, 작업 순서는 [커리큘럼 이전 계획](../../docs/curriculum-plan.md)에 있습니다. Notion 원문은 수정하지 않습니다. 사이트 단원은 학습 순서이며 워크북 차시와 구분합니다.

## 단원

| 단원 | 제목               | 워크북       | 현재 강의                                         |
| ---- | ------------------ | ------------ | ------------------------------------------------- |
| 0    | 클라우드와 EC2     | 1차시        | EC2, S3, Git, 첫 노드 실습                        |
| 1    | 스토리지와 CDN     | 2차시        | Block·File·Object                                 |
| 2    | 네트워킹           | 3차시        | 작성 전                                           |
| 3    | 확장성과 고가용성  | 4차시        | 작성 전                                           |
| 4    | 디커플링           | 5차시        | 작성 전                                           |
| 5    | 컨테이너           | 6차시        | VM·Docker·Kubernetes·볼륨, 컨테이너 종합 실습     |
| 6    | 서버리스           | 7차시        | HTTP·gRPC                                         |
| 7    | 관측               | Prometheus   | 지표·로그·트레이스, Prometheus                    |
| 8    | 전체 아키텍처 종합 | 7차시 보너스 | 작성 전                                           |
| 9    | CI/CD와 배포 전략  | 없음(보강)   | Recreate·Blue-Green·Canary·Shadow, 전환 종합 실습 |

강의가 없는 단원은 목차에 표시하지 않습니다. 전체 강의 목록은 [강의 MDX 본문 목록](../src/content/lesson-index.md)에 있습니다. BlockML에서 가져온 강의의 본문에는 아직 모델 학습·서빙 예시가 남아 있으며, 단원별 강의 작성 이슈에서 DevOps 예시로 바꿉니다.

## 작성 기준

질문을 던지고 바로 풀어 설명합니다. 쉬운 말 → 정확한 용어 → 구체적 예 → 다음 질문 순서로 씁니다. 유머는 상황을 기억하기 위한 짧은 문장으로 사용하며 개념 설명을 대신하지 않습니다.

워크북의 각 항목은 다음처럼 옮깁니다.

| 워크북 항목           | 사이트에서 쓰는 곳           |
| --------------------- | ---------------------------- |
| 목표                  | 강의 요약, 단원 소개         |
| 핵심 키워드           | MDX 본문, `concepts`         |
| 이번 차시 질문        | 이해 확인 문제, 성찰 질문    |
| 미션                  | 단원 종합 실습               |
| 구조적으로 정리해보기 | 노드 실습의 목표 구성        |
| 트러블 슈팅           | 실패 시나리오와 AI 조언 힌트 |

각 실습은 예상할 것, 조작할 것, 확인할 근거를 명시합니다. 브라우저 노드는 교육용 모형이며 실제 AWS를 실행하지 않습니다.

## 정확성·교육용 경계

| 항목     | 적용 기준                                                                 |
| -------- | ------------------------------------------------------------------------- |
| 스토리지 | RWO는 단일 노드이며 다중 Pod 가능, 공유 읽기에 무조건 RWX를 요구하지 않음 |
| 배포     | Shadow의 응답은 사용자에게 보내지 않음, 승격은 별도 판단                  |
| 관측     | 지표·로그·트레이스 분리, 알림은 자동 배포 명령이 아님                     |

활동의 수치·고정 응답은 교육용 모형이며 실제 도구 실행이 아닙니다.

## 본문 노드 예제 배치

| 강의                 | 확인할 관계                                |
| -------------------- | ------------------------------------------ |
| S3 객체              | 객체 읽기 → EC2 실행 → 결과 보관           |
| 이미지·컨테이너      | 같은 이미지에서 실행되는 두 컨테이너       |
| Kubernetes 제어·요청 | 원하는 실행 상태와 사용자 요청의 별도 경로 |
| PV·PVC               | Pod의 참조와 PVC·PV의 바인딩               |
| Canary               | 기존·새 버전으로 전달되는 실제 사용자 요청 |

예제는 완성 흐름 추적 → 빠진 연결 채우기 → 이유 확인 → 관련 종합 실습으로 이어집니다.
