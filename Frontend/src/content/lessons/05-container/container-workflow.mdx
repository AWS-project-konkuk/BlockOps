## 이미지는 만들었는데 서비스가 뜨지 않는다면?

커밋 `v2`를 GitHub Actions가 빌드해 이미지를 만들었습니다. 이 이미지를 ECR에 올리고, 프라이빗 서브넷의 주문 API 서비스(Fargate)가 받아 실행해야 합니다. 그런데 서비스가 뜨지 않습니다. 이미지는 어디서 멈췄을까요?

## 준비된 노드

| 노드 | 처음 상태 |
| --- | --- |
| **주문 API 저장소 · 빌드 파이프라인** | 커밋 v2를 빌드해 이미지를 만듭니다. |
| **주문 API 이미지**(ECR) | 빌드 결과를 받아 보관하고 내보냅니다. |
| **앱 서브넷** | 프라이빗 서브넷이고, 바깥으로 나가는 경로가 없습니다. |
| **주문 API 서비스**(ECS) | Fargate로 태스크 2개를 띄웁니다. S3 권한이 인스턴스 프로파일로 되어 있습니다. |
| **응답 확인** | 서비스의 응답으로 100건이 모두 응답받았는지 확인합니다. |

## 실습 순서

1. **빌드 파이프라인**의 이미지를 **ECR**에, ECR의 이미지를 **주문 API 서비스**에 연결하세요.
2. 서비스의 **응답**을 **응답 확인**에 연결하고 실행합니다.
3. 첫 번째 실패에서 이미지가 왜 서비스에 닿지 않는지 읽고 **앱 서브넷**을 고치세요.
4. 두 번째 실패에서 Fargate에서 쓸 수 없는 설정을 찾아 **주문 API 서비스**의 권한을 고치세요.

<LessonSummary>

컨테이너 서비스는 코드 → 빌드 → 레지스트리 → 오케스트레이터 순서로 이미지가 흐릅니다. 프라이빗 서브넷의 태스크는 NAT 같은 바깥 경로가 있어야 ECR에서 이미지를 받고, Fargate에는 관리할 호스트가 없으므로 권한은 태스크 역할로 줍니다. 실행 결과의 서비스 메시지에서 실제로 띄운 이미지 태그도 확인합니다.

</LessonSummary>
