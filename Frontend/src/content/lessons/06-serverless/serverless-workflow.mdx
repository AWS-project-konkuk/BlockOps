## 함수와 테이블은 있는데 주문은 어디로 가야 할까요?

주문 API(API Gateway), 주문 저장 함수(Lambda), 주문 테이블(DynamoDB)을 만들었습니다. 사용자는 `/api/orders`로 주문 100건을 보냅니다. 세 서비스를 어떻게 이어야 주문이 테이블에 기록될까요?

## 준비된 노드

| 노드 | 처음 상태 |
| --- | --- |
| **사용자** | `/api/orders`로 요청 100건을 보냅니다. 주문 API에 연결되어 있습니다. |
| **주문 API**(API Gateway) | HTTP API입니다. |
| **주문 저장 함수**(Lambda) | Node.js 런타임입니다. |
| **주문 테이블**(DynamoDB) | 파티션 키가 `date`이고, 프로비저닝 용량입니다. |
| **응답 확인** | 주문 테이블까지 기록된 요청 수를 셉니다. |

## 실습 순서

1. **주문 API**의 통합 호출을 **주문 저장 함수**에, 함수의 쿼리를 **주문 테이블**에 연결하세요.
2. 주문 테이블의 **처리 결과**를 **응답 확인**에 연결하고 실행합니다.
3. 쓰기가 거절된 이유를 읽고 **주문 테이블**의 파티션 키를 고치세요.
4. 성공하면 함수의 런타임을 Java로 바꿔 실행 결과의 콜드 스타트 시간을 비교해 보세요.

<LessonSummary>

서버리스 백엔드는 API Gateway가 요청을 받고, Lambda가 처리하고, DynamoDB가 저장하는 구성입니다. 서버를 띄우지 않아도 되지만, DynamoDB의 파티션 키가 한 값에 몰리면 그 파티션의 용량을 넘어 쓰기가 거절됩니다. 키는 고르게 퍼지는 값으로 정합니다.

</LessonSummary>
