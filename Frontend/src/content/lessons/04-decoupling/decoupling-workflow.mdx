## 주문은 들어왔는데 고객은 메일을 못 받았다면?

주문 API로 주문 100건이 들어왔습니다. 주문 함수는 재고 큐에 메시지를 넣고, 재고 함수가 재고를 차감합니다. 그런데 고객에게는 주문 완료 메일이 한 통도 가지 않았고, 재고는 주문보다 많이 빠졌습니다. 무엇을 바꿔야 할까요?

## 준비된 노드

| 노드 | 처음 상태 |
| --- | --- |
| **주문 API**(API Gateway) · **주문 함수** | 주문 100건을 받아 메시지를 보냅니다. |
| **재고 큐**(SQS) · **재고 차감 함수** | 표준 큐입니다. 주문 함수와 바로 연결되어 있습니다. |
| **주문 완료 주제**(SNS) | 아직 아무 것과도 연결되어 있지 않습니다. |
| **메일 큐**(SQS) · **메일 발송 함수** | 아직 연결되어 있지 않습니다. |
| **주문 처리 확인** | 재고 차감 기록에 중복이 없는지, 메일이 발송됐는지 확인합니다. |

## 실습 순서

1. 그대로 실행해 무엇이 빠졌는지 확인하세요.
2. 주문 함수의 메시지를 **주문 완료 주제**로 보내고, 주제를 **재고 큐**와 **메일 큐**에 연결하세요. 주문 함수에서 재고 큐로 바로 가던 선은 지웁니다.
3. 메일 큐를 **메일 발송 함수**에, 메일 발송 함수의 메시지를 **주문 처리 확인**의 메일 발송 기록에 연결하고 실행하세요.
4. 재고가 몇 건 중복 차감됐는지 확인하고, 재고 큐의 유형을 바꿔 다시 실행하세요.

메일 큐의 유형은 그대로 둬도 됩니다. 왜 그래도 되는지 이해 확인에서 답합니다.

<LessonSummary>

생산자가 소비자를 하나씩 직접 부르면 할 일이 늘 때마다 생산자를 고쳐야 하고 빠뜨리기도 쉽습니다. SNS 주제에 한 번 게시하고 큐들이 구독하게 하면 일이 독립적으로 나뉩니다. 큐 유형은 일의 성격에 맞춰, 한 번만 일어나야 하는 재고 차감은 FIFO로 둡니다.

</LessonSummary>
