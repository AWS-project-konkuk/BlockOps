## 1,000건이 몰렸는데 주문이 하나도 안 들어간다면?

세일 첫날 사용자 요청 1,000건이 웹 ALB로 들어옵니다. 요청은 웹 서버 그룹을 지나 주문 DB에 기록되어야 완료됩니다. 그런데 주문이 한 건도 완료되지 않습니다. 어디부터 고쳐야 할까요?

## 준비된 노드

| 노드 | 처음 상태 |
| --- | --- |
| **사용자** | 요청 1,000건을 보냅니다. |
| **웹 ALB** | 헬스 체크 경로가 `/status`입니다. |
| **웹 서버 그룹** | 프라이빗 앱 서브넷(2a)에 있고, 조정 정책 없이 2대로 고정되어 있습니다. 한 대는 요청 100건을 처리합니다. |
| **주문 DB** | 프라이빗 DB 서브넷(2c)에 있고 Multi-AZ가 꺼져 있습니다. |
| **응답 확인** | 주문 DB까지 처리된 요청 수를 셉니다. |

## 실습 순서

1. **주문 DB**의 **처리 결과**를 **응답 확인**에 연결하고 실행하세요.
2. 첫 번째 실패 메시지를 읽고 **웹 ALB**의 헬스 체크 경로를 고칩니다.
3. 두 번째 실패에서 몇 건이 실패했는지 확인하고, **웹 서버 그룹**의 조정 정책과 최대 수를 고쳐 1,000건을 모두 처리하세요.
4. 성공하면 **VPC**를 선택해 **장애 실험**을 `ap-northeast-2c 중단`으로 바꾸고 다시 실행합니다.
5. 주문 DB의 설정을 바꿔 가용 영역이 멈춰도 주문이 들어가게 하세요.

웹 서버 그룹은 처음부터 두 가용 영역에 분산 배치되어 있습니다. 배치를 한 가용 영역으로 바꾸고 2a를 멈추면 어떻게 되는지도 실행해 보세요.

<LessonSummary>

헬스 체크가 실패하면 ALB는 대상을 모두 빼서 요청을 보낼 곳이 없어집니다. 조정 정책이 없으면 Auto Scaling 그룹은 몰린 트래픽에도 서버를 늘리지 않고, 최대 수는 늘릴 수 있는 상한입니다. 가용 영역 장애는 웹 서버를 여러 영역에 나누고 DB를 Multi-AZ로 두어야 버틸 수 있습니다.

</LessonSummary>
