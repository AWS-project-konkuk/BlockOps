## DB도 인터넷에 그대로 노출되어 있다면?

EC2를 하나 만들고 그 안에 웹 서버와 DB를 모두 띄웠습니다. 공인 IP로 접속하니 웹 페이지가 잘 열립니다. 그런데 같은 IP로 DB 포트에도 누군가 접속을 시도하고 있습니다. 서버와 DB를 바깥에서 다르게 보이게 할 수는 없을까요?

## VPC는 내 네트워크의 벽이다

**VPC**(Virtual Private Cloud)는 AWS 안에서 논리적으로 격리된 내 네트워크입니다. VPC 안의 자원은 **프라이빗 IP**로 서로 통신하고, 바깥과 통신하려면 문을 따로 뚫어야 합니다. 그래서 필요한 자원만 공개하고 나머지는 숨길 수 있습니다.

VPC를 만들 때 쓸 IP 범위를 **CIDR**로 정합니다. `10.0.0.0/16`에서 `/16`은 앞의 16비트가 네트워크를 나타낸다는 뜻이라, 나머지 16비트로 약 65,000개의 주소를 쓸 수 있습니다. 숫자가 클수록 범위가 좁습니다.

| CIDR | 주소 수 | 쓰임 |
| --- | --- | --- |
| `10.0.0.0/16` | 65,536 | VPC 전체 |
| `10.0.1.0/24` | 256 | 서브넷 하나 |
| `10.0.2.0/28` | 16 | AWS 서브넷의 최소 크기 |

## 서브넷으로 VPC를 나눈다

**서브넷**은 VPC의 IP 범위를 잘게 나눈 구역입니다. 서브넷끼리는 범위가 겹치면 안 됩니다. 서브넷 하나는 **가용 영역**(AZ) 하나에 속합니다. 가용 영역은 리전 안의 물리적으로 떨어진 데이터 센터이고, 장애에 대비하려면 서브넷을 여러 가용 영역에 나눠 둡니다.

서브넷을 나누는 가장 큰 이유는 **공개 범위**입니다.

- **퍼블릭 서브넷**: 인터넷과 통신하는 경로가 있습니다. 웹 서버나 로드 밸런서를 둡니다.
- **프라이빗 서브넷**: 인터넷에서 직접 들어올 경로가 없습니다. DB와 내부 서버를 둡니다.

서브넷 자체에는 퍼블릭·프라이빗 스위치가 없습니다. 어떤 **라우팅 테이블**과 연결되었는지가 이를 정합니다. 다음 강의에서 다룹니다.

## 쓸 수 있는 IP는 생각보다 적다

`/24` 서브넷은 256개 주소지만, AWS는 각 서브넷에서 5개를 예약합니다.

| 주소 | 용도 |
| --- | --- |
| `x.x.x.0` | 네트워크 주소 |
| `x.x.x.1` | VPC 라우터 |
| `x.x.x.2` | DNS 서버 |
| `x.x.x.3` | 향후 사용 예약 |
| `x.x.x.255` | 브로드캐스트(지원하지 않지만 예약) |

그래서 실제로 쓸 수 있는 IP는 251개입니다. 최소 크기가 `/28`(16개, 실제 11개)인 이유도 이것입니다. 더 작으면 예약 주소를 빼고 나면 남는 게 거의 없습니다.

<LessonSummary>

VPC는 리전 안에서 격리된 내 네트워크이고, CIDR로 쓸 IP 범위를 정합니다. 서브넷은 VPC를 겹치지 않게 나눈 구역으로, 가용 영역 하나에 속합니다. 웹 서버는 퍼블릭 서브넷, DB는 프라이빗 서브넷에 두어 공개 범위를 나눕니다.

- 서브넷마다 5개 IP를 AWS가 예약하므로 `/24`에서 쓸 수 있는 IP는 251개입니다.
- 퍼블릭과 프라이빗을 정하는 것은 서브넷이 아니라 연결된 라우팅 테이블입니다.

</LessonSummary>
