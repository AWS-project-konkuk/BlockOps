## 요청은 VPC 문 앞까지 왔는데 왜 서버는 조용할까요?

사용자의 HTTPS 요청 100건이 인터넷 게이트웨이까지 들어왔습니다. 웹 서버는 퍼블릭 서브넷에 있고, DB는 프라이빗 서브넷에 있습니다. 그런데 웹 서버는 아무 응답도 하지 않습니다. 요청은 어디서 멈췄을까요?

## 준비된 노드

| 노드 | 처음 상태 |
| --- | --- |
| **사용자** | HTTPS(443)로 요청 100건을 보냅니다. |
| **인터넷 게이트웨이** | VPC에 붙어 있습니다. |
| **퍼블릭 서브넷** | 라우팅 테이블에 0.0.0.0/0 경로가 없습니다. |
| **웹 서버**(EC2) | 보안 그룹이 SSH 22번만 허용합니다. 퍼블릭 IP가 있습니다. |
| **프라이빗 서브넷 · 상품 DB** | 바깥으로 나가는 경로만 NAT로 둡니다. |
| **응답 확인** | 웹 서버의 응답으로 100건이 모두 응답받았는지 확인합니다. |

## 실습 순서

1. **인터넷 게이트웨이**의 HTTP 요청 출력을 **웹 서버**에 연결하고, 웹 서버의 **응답**을 **응답 확인**에 연결하세요.
2. 실행하고 실패 메시지를 읽으세요. **퍼블릭 서브넷**을 선택해 라우팅 테이블 경로를 고칩니다.
3. 다시 실행해 두 번째 실패를 확인하고, **웹 서버**의 보안 그룹 인바운드를 고칩니다.
4. 100건이 모두 응답받으면, 웹 서버의 퍼블릭 IP를 없앴을 때 어떻게 되는지도 실행해 보세요.

DB는 프라이빗 서브넷에 그대로 둡니다. 퍼블릭 서브넷으로 옮기면 어떤 일이 생기는지는 3단원에서 다시 봅니다.

<LessonSummary>

인터넷 요청이 EC2에 닿으려면 인터넷 게이트웨이, 서브넷 라우팅 테이블의 0.0.0.0/0 경로, 퍼블릭 IP, 보안 그룹의 포트 허용이 모두 맞아야 합니다. 실패 메시지는 요청이 멈춘 곳을 알려 주므로, 경로에서 검문소로 한 단계씩 좁혀 가며 고칩니다. DB는 프라이빗 서브넷에 두고 웹 서버만 접근하게 합니다.

</LessonSummary>
