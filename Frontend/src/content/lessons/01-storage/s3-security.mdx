## 이미지를 올렸는데 왜 403일까요?

상품 사진 `logo.png`를 S3 버킷에 올리고 주소를 브라우저에 붙여 넣었습니다. 돌아온 건 사진이 아니라 `403 Forbidden`입니다. 파일은 분명 버킷에 있는데, 누가 막은 걸까요?

결론부터 말하면 막은 건 S3의 **기본값**입니다. S3의 모든 리소스는 처음에 비공개이고, 리소스를 만든 계정과 권한을 받은 IAM 주체만 접근할 수 있습니다. 공개는 실수로 일어나면 안 되는 일이라 일부러 열어야만 열립니다.

## 버킷과 객체

S3는 **객체 스토리지**입니다. 파일 하나와 그 파일을 설명하는 메타데이터를 합친 것이 **객체**이고, 객체를 담는 저장소가 **버킷**입니다. 객체는 폴더 경로처럼 보이는 **키**(`static/logo.png`)로 찾습니다.

| 스토리지 클래스 | 특징 | 어울리는 데이터 |
| --- | --- | --- |
| S3 Standard | 자주 읽고 지연이 짧음 | 웹 사이트 파일, 자주 쓰는 데이터 |
| S3 Intelligent-Tiering | 읽는 빈도에 맞춰 자동 이동 | 패턴을 모르는 데이터 |
| S3 Standard-IA | 저장은 싸고 읽을 때 비쌈 | 가끔 꺼내는 백업 |
| S3 Glacier 계열 | 가장 싸지만 꺼내는 데 시간이 걸림 | 오래 보관만 하는 자료 |

**버전 관리**를 켜면 같은 키에 덮어써도 이전 버전이 남아서 실수로 지운 파일을 되살릴 수 있습니다. **수명 주기 규칙**으로는 오래된 객체를 싼 클래스로 옮기거나 지웁니다.

## 누가 접근할 수 있는지 정하는 세 가지

1. **IAM 정책**: 사용자·역할에 붙입니다. "이 사람은 어떤 버킷에서 무엇을 할 수 있다."
2. **버킷 정책**: 버킷에 붙입니다. "이 버킷에는 누가 무엇을 할 수 있다." 사람 수백 명에게 일일이 권한을 주는 대신 버킷 한 곳에서 관리하고, CloudFront 같은 **서비스**에도 권한을 줄 수 있어서 핵심입니다.
3. **퍼블릭 액세스 차단**(Block Public Access): 위 정책이 버킷을 공개하려고 해도 막는 안전장치입니다. 2023년 4월 이후 만든 버킷은 기본으로 켜져 있습니다.

평가 순서는 IAM과 같습니다. 아무 허용이 없으면 거부, 허용이 있어도 **명시적 거부(Deny)가 있으면 거부**입니다.

## 그러면 사진은 어떻게 보여 주나요?

버킷을 공개하면 사진은 보이지만, 누구나 S3 주소로 바로 받아 갈 수 있고 실수로 다른 파일까지 공개될 위험이 생깁니다. 대신 **버킷은 비공개로 두고, CloudFront에만 읽기 권한을 주는** 구성을 씁니다. 다음 강의에서 이 CloudFront를 다룹니다.

<LessonSummary>

S3는 버킷에 객체를 키로 보관하는 객체 스토리지입니다. 모든 버킷과 객체는 기본으로 비공개이고, IAM 정책은 사람·역할 쪽에서, 버킷 정책은 버킷 쪽에서 권한을 정합니다. 퍼블릭 액세스 차단은 정책이 버킷을 공개하려 해도 막는 마지막 안전장치입니다.

- 403이 뜨면 IAM 정책 → 버킷 정책 → 퍼블릭 액세스 차단 순서로 확인합니다.
- 전 세계에 파일을 보여 줄 때도 버킷은 비공개로 두고 CloudFront(OAC)에만 읽기를 허용합니다.

</LessonSummary>
