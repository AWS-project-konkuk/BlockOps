## 버킷은 비공개인데 사용자는 로고를 받을 수 있을까요?

쇼핑몰 로고 `/static/logo.png`를 사용자 100명이 요청합니다. 버킷은 퍼블릭 액세스 차단이 켜진 비공개 상태입니다. 버킷을 공개하지 않고 모두에게 로고를 보여 줄 수 있을까요?

## 준비된 노드

| 노드 | 역할 |
| --- | --- |
| **사용자** | 로고 파일 요청 100건을 보냅니다. |
| **정적 파일 배포**(CloudFront) | 엣지 캐시로 응답하고, 캐시에 없으면 버킷에서 가져옵니다. |
| **정적 파일 버킷**(S3) | 퍼블릭 액세스 차단이 켜진 비공개 버킷입니다. |
| **응답 확인** | 캐시 응답과 버킷 응답을 합쳐 100건이 모두 응답받았는지 확인합니다. |

## 실습 순서

1. 그대로 **실습 실행**을 누르세요. 버킷이 왜 요청을 막는지 결과에서 확인합니다.
2. 사용자의 요청을 **정적 파일 배포**로 보내고, 정적 파일 배포의 **오리진 요청**을 버킷에 연결하세요. 사용자에서 버킷으로 바로 가는 선은 지웁니다.
3. 정적 파일 배포의 **캐시 응답**을 **응답 확인**에 연결하고 다시 실행하세요. 이번에는 새 로고 대신 예전 로고가 보이는 문제를 만납니다.
4. 정적 파일 배포를 선택해 **새 버전 배포 후** 설정을 고친 뒤 실행해, 요청 100건이 모두 응답받는지 확인하세요.

<LessonSummary>

버킷은 비공개로 둔 채 사용자를 CloudFront로만 보내면, OAC로 허용받은 CloudFront만 버킷을 읽습니다. 같은 파일 요청은 엣지 캐시가 대부분 응답하고, 캐시에 없는 요청만 버킷까지 갑니다. TTL이 긴 캐시는 배포 뒤에도 예전 파일을 주므로 Invalidation이나 파일 이름 버저닝으로 새 버전을 반영합니다.

</LessonSummary>
