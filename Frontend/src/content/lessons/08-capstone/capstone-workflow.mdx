## 주문이 하나도 DB에 들어가지 않는다면?

`shop.example.com`의 주문 버튼을 누르면 오류가 납니다. 구성은 지금까지 배운 그대로입니다. Route 53, 인터넷 게이트웨이, ALB, 프라이빗 서브넷의 ECS 서비스, Multi-AZ RDS. 그런데 설정 몇 군데가 잘못되어 있습니다. 어디부터 볼까요?

## 준비된 구성

| 노드 | 역할 |
| --- | --- |
| **사용자 → shop.example.com**(Route 53) | HTTPS 주문 요청 100건이 들어옵니다. |
| **인터넷 게이트웨이 → 주문 ALB** | VPC로 들어온 요청을 서비스에 나눕니다. |
| **앱 서브넷(2a) · 주문 API 서비스**(ECS) | ECR의 이미지로 주문을 처리합니다. |
| **DB 서브넷(2c) · 주문 DB**(RDS) | Multi-AZ로 주문을 저장합니다. |
| **응답 확인** | 주문 DB까지 처리된 주문 수를 셉니다. |

연결은 모두 되어 있습니다. 이번에는 선을 고치지 않고 **설정만** 고칩니다.

## 실습 순서

1. 실행하고, 결과에 나온 **처음 실패한 노드**와 이유를 읽으세요.
2. 그 노드를 선택해 메시지가 가리키는 설정을 고치고 다시 실행합니다.
3. 주문 100건이 모두 DB까지 들어갈 때까지 반복하세요. 장애는 세 가지입니다.
4. 마지막으로 VPC의 장애 실험을 켜서 Multi-AZ DB가 버티는지도 확인해 보세요.

<LessonSummary>

장애는 한꺼번에 보이지 않고, 앞의 문제를 고쳐야 다음 문제가 드러납니다. 요청 경로를 앞에서부터 따라가며 처음 실패한 노드의 메시지를 읽고, 그 노드가 속한 단원의 규칙으로 설정을 고칩니다. 로드 밸런서의 헬스 체크와 리스너, 프라이빗 서브넷의 바깥 경로처럼 단원마다 배운 확인 지점이 진단의 목록이 됩니다.

</LessonSummary>
